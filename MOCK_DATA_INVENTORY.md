## 1. `data/dna/` — model input data

### `data/dna/rookie_projections_2026.json`
All 214 rookie entries (`usage_curve`, `efficiency_curve`, `static_projection`: target_share, catch_rate, yac_per_rec, adot, elusiveness, top_speed_mph, etc.) are generic **position-baseline placeholders**, not per-player values.
- Self-flagged in `_metadata.note`: *"Skeleton generated by build_rookie_projections_v_0_1_0.py from Phase 3's rookie flags. Every value below is a rough position-baseline placeholder, NOT a real per-player projection — edit before relying on this for a live sim."*
- Generator: `scripts/roster_management/build_rookie_projections_v_0_1_0.py` — "Position-baseline placeholder values — deliberately modest."
- Promotion path: `scripts/roster_management/promote_rookie_to_flat_v_0_1_0.py` (still placeholder-quality after promotion).
- **Replace by:** hand-editing per player.

### `data/dna/trench_dna.json`
- `"2026"` season entry is a **real-data carry-forward** (copies each team's actual 2025 composite metrics), not synthetic — but it's a scaffolded "shell" for a season with no measured data yet.
- `blitz_rate`, `off_pass_block_win_rate`, `times_to_pressure_sec` are **always empty (`{}`)** across every season/team, in every year. Documented in the file's own `_metadata` and `docs/sims/inputs/README.md:99`. Confirmed unused except `blitz_rate`, which is buildable but deliberately deferred.
- **Replace by:** revisit ~2027–2028 once FTN data has enough seasons (see `FUTURE_DEVELOPMENT.md:21-27`).

### `data/dna/trench_tiers_2025.json`
- `"CIN"` entry: `run_block_tier`, `pass_block_tier`, `run_stuff_tier`, `pass_rush_tier` hardcoded to neutral `3` — confirmed dead/unread fields.
- `qb_cpoe_z: 2.0` is a hand-picked estimate, not computed; the original hand-curation method could not be reliably reconstructed (`docs/sims/inputs/README.md:142`).

### `data/dna/coach_dna.json`
Five 2026 first-time HCs with no real HC-level nflfastR history (via `scripts/roster_management/merge_2026_coach_placeholders.py`):
- **Klint Kubiak** — aliased from Mike Macdonald's real entry (a proxy, not a placeholder).
- **Jesse Minter, Jeff Hafley, Joe Brady, Todd Monken** — set to freshly-computed **league-average** values, each carrying an explicit `_note: PLACEHOLDER` field. Brady/Monken are pending a tenure-filtered PBP rebuild.

### `data/dna/coach_coordinator_levers_2026.csv`
Rows for coordinators with no real 2015–2025 PBP history under their own name (Mike LaFleur/ARI, Jesse Minter/BAL, Joe Brady/BUF, etc.) are **left blank on purpose**: *"NO REAL HISTORY under this name in 2015-2025 PBP — left blank for Cam to hand-fill, per 2026-08-17 session (not auto-filled with a league-average placeholder)."*

### `data/dna/handcuff_overrides_2026.csv`
Header row only — empty stub, zero data rows.

### `data/dna/zone_usage_overrides_2026.csv` (+ `zone_usage_overrides_2026_notes.md`)
`rz_target_share`, `rz_carry_share`, `five_target_share`, `five_carry_share` are pre-populated by copying each player's flat season-long share into both red-zone/five-yard zones — no zone-specific projection has been done. Notes file: *"Treat every value here as a placeholder until hand-edited."* Not wired into `game_engine.py` or any blend pipeline yet.
- Generator: `scripts/roster_management/export_zone_usage_overrides_v_0_1_0.py`.

### `data/dna/preseason_overrides_2026.csv` (+ `preseason_overrides_2026_notes.md`)
Cam's primary hand-tuned 2026 sheet — mostly real judgment, but with documented interim placeholders:
- Jordyn Tyson (NO) — "Set to the league-wide WR average for now as a placeholder."

### `data/dna/coordinator_atlas.json` — **not placeholder data**
Currently deleted from the working tree. Contains real computed per-coach `off_proe`/`def_proe_allowed` values. Deliberately retired 2026-07-16 after being merged into `coach_dna.json`; a later full rebuild of `coach_dna.json` silently wiped the merged field back out. `scripts/roster_management/merge_coach_proe.py` now re-pulls the real data from pinned commit `17e8a69` instead of requiring the file on disk. Included here only to flag that its absence is intentional, not a data-quality gap — rerun the merge script any time `coach_dna.json` is rebuilt from scratch.

## 2. `src/` — application/model code

- **`src/api/app.py:2228`** — `_compute_ownership()`: computes **synthetic** V1 DFS ownership via two-factor softmax + log-normal noise. Self-labeled synthetic; used live, not a real ownership feed.
- **`src/api/app.py:1258-1270`** — `live_games()`: pregame/"scheduled" games get hardcoded default situational fields (`down=1, distance=10, home_wp=away_wp=50.0`) rather than nulls, so the frontend renders cleanly before real state exists. Intentional UX default, not a gap.

## 3. `frontend/` and `frontend_analysis/` — UI mock-data fallback

Both React frontends use a deliberate **offline-fallback pattern**: `safeFetch()` hits the real backend first and only falls back to hardcoded mock data on failure, with a console warning and (in `frontend/`) a visible `SandboxBadge.jsx` indicator.

- **`frontend_analysis/src/api.js`** — `MOCK_GAMES` (5 fabricated live games, e.g. PHI@KC 24-27), `MOCK_PLAYOFF_ODDS`, `MOCK_PLAY_BY_PLAY`, `MOCK_FOURTH_DOWNS`, `MOCK_GAME_STATS`, `MOCK_CHESS_EVALUATOR`. Documented as intentional in that directory's `README.md`.
- **`frontend/src/api.js`** — `MOCK_WEEKS`, `MOCK_GAMES`, `MOCK_ROSTERS`, `generateMockGames()`, `generateMockLineups()`, same fallback pattern for the DFS optimizer UI.
- **`frontend/src/components/SandboxBadge.jsx`** — UI badge shown whenever a page is displaying mock/sandbox data instead of live backend data (see component's own `README.md:9`).
- **`frontend/src/pages/InDevelopment.jsx`** — entirely mock/WIP page (its own `README.md:31`: "WIP placeholder"). Hardcoded `mockProps` (player prop bets), `mockFutures`, `mockWar` (WAR/salary table), and a hardcoded `optLineup` starter array — fabricated scaffolding for not-yet-built features.

All frontend mock data is consistently `MOCK_`/`mock`-prefixed and gated behind fetch failure or an explicit WIP page — none of it is disguised as real.
